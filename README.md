# Kitanishi Lab 機器・部屋予約システム

研究室内の共通機器・実験スペース・部屋などの予約を、ブラウザから確認・登録・変更・削除するためのWebアプリです。

予約データと機器・部屋の情報はGoogleスプレッドシートに保存されます。カレンダー連携を有効にした予約は、管理用の共通Googleカレンダーにも登録され、予約者には個人カレンダーへ追加するための案内メールが送信されます。

---

# 1. 使用者・予約者向けガイド

## 1.1 システムの概要

ブラウザで予約ページを開くと、研究室の機器・部屋ごとの予約状況を確認できます。専用アプリのインストールは不要です。スマートフォン、タブレット、PCのブラウザから利用できます。

通常運用時は、画面右上に`Google Drive 連携中`と表示されます。`デモモード (ローカル)`の場合、その端末内だけに保存される試用状態です。他の利用者とは共有されないため、実際の予約には使用しないでください。

## 1.2 搭載されている機能

### 予約状況の表示

- **タイムライン**：選択した1日について、すべての機器・部屋の予約を横軸の時間帯で表示します。
- **機器・部屋別予約**：選択した機器・部屋について、1か月分の予約を日ごとのタイムラインで表示します。
- **予約一覧**：すべての予約を日時順に表示します。使用者名、機器・部屋名、備考で検索できます。
- **24時間表示**：通常の8:00〜22:00表示と、0:00〜24:00表示を切り替えられます。

### 予約の登録・編集

- 予約時間は15分刻みで指定できます。
- `+30分`、`+1時間`、`+2時間`、`+4時間`ボタンで終了時間を設定できます。
- 予約ブロックの色を20色から選択できます。
- 備考・使用目的を記録できます。
- 同じ機器・部屋で時間が重なる予約は登録できません。
- 過去に同じ使用者名で登録したメールアドレスと備考は、次回入力時の候補として表示されます。

### カレンダーとメール通知

`カレンダー追加用メールを受け取る`を有効にして予約すると、次の処理が行われます。

1. 予約が管理用の共通Googleカレンダーに登録されます。
2. 入力したメールアドレスに、表示名`機器予約のお知らせ`で案内メールが届きます。
3. メール内の`Googleカレンダーに追加`ボタンを押すと、予約内容を自分のGoogleカレンダーに追加できます。

メール件名は`[機器予約] ：機器・部屋名`です。この方式では予約者は共通カレンダーのゲストとして招待されません。メールの実際の送信元アドレスは、予約システムのApps Scriptを実行しているGoogleアカウントです。`機器予約のお知らせ`は、このシステムが送る案内メールだけに適用される表示名です。

## 1.3 予約状況を確認する

### 1日分を確認する

1. `タイムライン`を選択します。
2. `前日`、`今日`、`翌日`または日付入力欄で対象日を選択します。
3. 各機器・部屋の行に表示される予約ブロックを確認します。
4. ブロックにマウスを合わせると、使用者、時間、備考、最終編集日時が表示されます。

### 1か月分を確認する

1. `機器・部屋別予約`を選択します。
2. 対象の機器・部屋をプルダウンから選択します。
3. `前月`、`今月`、`翌月`で対象月を移動します。

### 予約を検索する

1. `予約一覧`を選択します。
2. 検索欄に使用者名、機器・部屋名、または備考の一部を入力します。

## 1.4 新しく予約する

次のいずれかの方法で予約画面を開きます。

- 右上の`新規予約`を押す。
- タイムラインの空いている時間帯をドラッグする。
- 機器・部屋別予約画面の日付行を選択する。

予約画面では次の項目を入力します。

| 項目 | 必須 | 内容 |
| --- | --- | --- |
| 予約する機器・部屋 | 必須 | 利用する対象を選択します。 |
| 使用者名 | 必須 | 実際に機器・部屋を使用する人の名前を入力します。 |
| 開始日時・終了日時 | 必須 | 15分刻みで指定します。終了日時は開始日時より後にします。 |
| カレンダー追加用メール | 任意 | 有効にすると、共通カレンダーへの登録と案内メール送信が行われます。 |
| 予約者のメールアドレス | 上記を有効にした場合は必須 | カレンダー追加用メールの送信先です。 |
| ラベルカラー | 任意 | タイムライン上の予約色です。 |
| 備考・使用目的 | 任意 | 実験内容や注意事項などを入力します。 |

入力後、`予約を確定する`を押します。同じ機器・部屋ですでに予約されている時間と重なる場合は、警告が表示されて登録されません。

## 1.5 Googleカレンダーへ追加する

1. 予約時に`カレンダー追加用メールを受け取る`を有効にします。
2. 自分のメールアドレスを入力して予約を確定します。
3. 届いたメールの`Googleカレンダーに追加`を押します。
4. Googleカレンダーの確認画面で内容を確認し、保存します。

ボタンから追加した予定は、予約システム上の予定とは別に、予約者自身が所有する予定として作成されます。

## 1.6 予約を変更する

次のいずれかの方法で変更できます。

- 予約ブロックをクリックし、編集画面で内容を変更して`変更を保存する`を押す。
- タイムライン上の予約ブロックを別の時間帯または別の機器・部屋の行へドラッグする。
- `予約一覧`の`編集`を押す。

カレンダー連携を有効にした予約は、共通Googleカレンダー上でも自動更新され、変更案内メールが送られます。ただし、以前のメールボタンから個人カレンダーに追加した予定は自動更新されません。変更メールを受け取ったら、個人カレンダー上の古い予定を削除し、メール内のボタンから変更後の予定を追加してください。

## 1.7 予約を削除する

予約ブロックの`×`、編集画面の`予約を削除`、または予約一覧の`削除`を使用します。確認画面で承認すると予約が削除されます。

カレンダー連携を有効にした予約は、共通Googleカレンダーからも削除され、予約者へ削除通知メールが送られます。個人カレンダーへ追加済みの予定は自動削除されないため、削除通知を確認し、該当予定を手動で削除してください。

## 1.8 スマートフォンのホーム画面に追加する

- **iPhone／iPad（Safari）**：共有ボタン → `ホーム画面に追加`
- **Android（Chrome）**：メニュー → `ホーム画面に追加`または`アプリをインストール`

# 2. セットアップ・管理者向けガイド

## 2.1 システム構成

| 構成要素 | 役割 |
| --- | --- |
| GitHub Pages | `index.html`、`styles.css`、`app.js`、`manifest.json`を配信します。 |
| Google Apps Script（GAS） | ブラウザからの要求を処理し、スプレッドシート、共通カレンダー、メール送信を操作します。 |
| Googleスプレッドシート | 予約情報と機器・部屋情報を保存します。 |
| 共通Googleカレンダー | カレンダー連携を有効にした予約を管理します。 |
| MailApp | 予約の新規登録・変更・削除メールを送信します。 |

## 2.2 ファイル構成

| ファイル | 内容 |
| --- | --- |
| `index.html` | 画面構造、予約フォーム、設定画面 |
| `styles.css` | PC・スマートフォン向けの表示スタイル |
| `app.js` | 画面描画、重複確認、予約操作、GASとの通信 |
| `gas_backend.js` | GASバックエンド、スプレッドシート・カレンダー・メール処理 |
| `manifest.json` | ホーム画面追加用のPWA設定 |
| `README.md` | 利用・セットアップ・管理手順 |

## 2.3 セットアップに必要なもの

- 管理用のGoogleアカウント
- Googleスプレッドシート
- 機器予約専用の追加Googleカレンダー
- GitHubリポジトリとGitHub Pages

現在の`gas_backend.js`と`index.html`には、次の共通カレンダーIDが設定されています。

```text
c_01aebf09407246c7474ed74abe3704ebccd739af23e70f63b8d3ba176506f6cd@group.calendar.google.com
```

別のカレンダーを使用する場合は、`gas_backend.js`の`COMMON_CALENDAR_ID`と、`index.html`の設定画面に表示されるIDを変更してください。カレンダーIDには埋め込みURL全体ではなく、`@group.calendar.google.com`で終わるIDを指定します。

## 2.4 GoogleスプレッドシートとGASを設定する

### 1. スプレッドシートを作成する

1. Google Driveで新しいGoogleスプレッドシートを作成します。
2. 例として`KitanishiLab_機器予約データ`などの名前を付けます。
3. `拡張機能` → `Apps Script`を開きます。

### 2. バックエンドコードを登録する

1. Apps Scriptエディタの既存コードを削除します。
2. `gas_backend.js`の内容を貼り付けて保存します。

### 3. データベースを初期化する

1. 関数一覧から`setupDatabase`を選択します。
2. `実行`を押し、表示されるGoogleアカウントの権限確認を完了します。

`Resources`と`Reservations`の2シートが作成されます。

#### Resourcesシート

| 列 | 内容 |
| --- | --- |
| ID | 機器・部屋の内部ID |
| Name | 表示名 |
| Location | 設置場所・部屋番号 |
| Description | 説明・注意事項 |

#### Reservationsシート

| 列 | 内容 |
| --- | --- |
| ID | 予約の内部ID |
| ResourceId / ResourceName | 対象機器・部屋のIDと表示名 |
| StartTime / EndTime | 開始日時・終了日時 |
| UserName | 使用者名 |
| Notes | 備考・使用目的 |
| CreatedAt / UpdatedAt | 作成日時・最終更新日時 |
| Color | 予約ブロックの色 |
| GoogleEventId | 共通カレンダー上の予定ID |
| CalendarId | 予定を保存したカレンダーID |
| GuestEmail | 案内メールの送信先アドレス |

既存シートに不足列を追加する場合も`setupDatabase`を再実行できます。既存予約行は削除されません。

### 4. メール送信権限を承認する

1. 関数一覧から`authorizeMailService`を選択します。
2. `実行`を押してMailAppの利用権限を承認します。

この操作は通常、最初のセットアップ時に1回だけ必要です。

### 5. Webアプリとしてデプロイする

1. Apps Scriptエディタ右上の`デプロイ` → `新しいデプロイ`を開きます。
2. 種類として`ウェブアプリ`を選択します。
3. 次のように設定します。

| 設定 | 推奨値 |
| --- | --- |
| 説明 | `Kitanishi Lab 予約API` |
| 実行するユーザー | `自分` |
| アクセスできるユーザー | 研究室のGoogle Workspace環境に応じて選択 |

4. デプロイし、末尾が`/exec`のウェブアプリURLをコピーします。

`実行するユーザー：自分`の場合、スプレッドシート、共通カレンダー、メール送信はデプロイした管理者の権限で実行されます。

## 2.5 GitHub Pagesを設定する

1. GitHubリポジトリに`index.html`、`styles.css`、`app.js`、`manifest.json`、`README.md`を配置します。
2. リポジトリの`Settings` → `Pages`を開きます。
3. `Deploy from a branch`を選択します。
4. 公開に使用するブランチ（例：`main`または`GmailautoSending`）と`/(root)`を選択します。
5. 保存し、発行されたGitHub Pages URLへアクセスします。

リポジトリがPublicの場合、GitHub Pagesの画面だけでなくリポジトリ内のコードも公開されます。パスワード、アクセストークン、秘密鍵などをファイルへ記載しないでください。共通カレンダー自体の公開範囲はGoogleカレンダー側の共有設定で別途管理します。

## 2.6 フロントエンドとGASを接続する

1. GitHub Pagesで公開した予約画面を開きます。
2. 右上の`Drive設定`を押します。
3. GASのウェブアプリURLを入力します。
4. `設定を保存して接続`を押します。
5. 右上が`Google Drive 連携中`になることを確認します。

GAS URLはブラウザのlocalStorageに保存されます。そのため、別のPC、別のブラウザ、シークレットウィンドウ、またはブラウザデータ削除後には再設定が必要です。すべての利用端末で設定を省くには、フロントエンド側に`window.DEFAULT_GAS_URL`を定義する必要があります。ただし、GAS URLを認証用の秘密情報として扱うことはできません。

## 2.7 初回の動作確認

1. 予約画面が`Google Drive 連携中`になっていることを確認します。
2. 管理者自身のメールアドレスでテスト予約を登録します。
3. `Reservations`シートと共通Googleカレンダーに予約が追加されたことを確認します。
4. 表示名`機器予約のお知らせ`、件名`[機器予約] ：機器・部屋名`のメールが届くことを確認します。
5. メールの`Googleカレンダーに追加`から予定を保存できることを確認します。
6. 重複予約が拒否されることを確認します。
7. テスト予約を変更・削除し、共通カレンダーと通知メールの動作を確認します。

## 2.8 日常の運用・管理

### 機器・部屋を管理する

画面右上の`機器・部屋の管理`から、機器・部屋の追加、編集、表示順変更、削除ができます。削除前に、その機器・部屋に予約が残っていないことを確認してください。フロントエンドでは関連予約数を確認し、予約がある場合は削除を止めます。

### 予約データを確認する

通常はWeb画面から操作します。障害調査やバックアップ時には`Reservations`シートで確認できます。列の順序や見出しはGASが固定位置で使用するため、手作業で並べ替えたり削除したりしないでください。

### コードを更新する

| 変更ファイル | 必要な操作 |
| --- | --- |
| `index.html`、`styles.css`、`app.js`、`manifest.json`、`README.md` | GitHubへコミットし、GitHub Pagesの反映を待ちます。 |
| `gas_backend.js` | Apps Scriptへ反映し、新しいバージョンとしてWebアプリを再デプロイします。 |

CSSやJavaScriptが更新されない場合は、`index.html`の読み込みURLに付いている`?v=`の値を変更するとブラウザキャッシュを回避できます。

```html
<link rel="stylesheet" href="styles.css?v=20260910-1">
<script src="app.js?v=20260910-1"></script>
```

### バックアップとブランチ保護

スプレッドシートは定期的にコピーするか、Google Driveの版履歴を確認してください。大きなコード変更前にはGitHub上でブランチまたはタグを作成します。公開に使うブランチには、少なくとも削除禁止とforce push禁止のRulesetを設定することを推奨します。

## 2.9 現在の仕様上の注意事項

### 個人カレンダーは自動更新されない

メールボタンから作成された個人カレンダー上の予定は予約システムとは別の予定です。そのため予約変更・削除は自動反映されません。共通カレンダー上の予定は自動更新・削除されます。

### 利用者と管理者の権限が分離されていない

現在の画面には利用者ログイン、管理者ログイン、操作権限の区別がありません。予約ページへアクセスできる利用者は、画面上から予約の編集・削除と機器・部屋の管理操作を行えます。

また、GASウェブアプリを`全員`に公開した場合、URLへアクセスできる第三者からAPIを呼び出される可能性があります。研究室外へURLを広く公開せず、可能であれば大学のGoogle Workspaceユーザーなどにアクセス範囲を限定してください。

### メール送信数には上限がある

MailAppにはGoogleアカウント種別に応じた1日あたりの送信上限があります。多数の予約・変更を短時間に行う場合は、Apps Scriptの実行履歴と残り送信可能数を確認してください。

### デモモードのデータは共有されない

デモモードの予約と機器情報はブラウザのlocalStorageだけに保存されます。ブラウザデータを削除すると失われ、他の端末には同期されません。

## 2.10 トラブルシューティング

### `指定された時間帯には既に他の予約が入っています`と表示される

同じ機器・部屋の予約時間が少しでも重複しています。時間または対象機器・部屋を変更してください。

### `Google Driveからのデータ取得に失敗しました`と表示される

- `Drive設定`に末尾が`/exec`の正しいGAS URLが入力されているか確認します。
- Webアプリのアクセス範囲を確認します。
- Apps Scriptの`実行数`画面でエラーを確認します。
- GASを変更した直後なら、新バージョンを再デプロイしたか確認します。

接続に失敗するとアプリはデモモードへ切り替わります。デモモードのまま実予約を登録しないよう注意してください。

### 共通Googleカレンダーに予定が作成されない

- 予約時に`カレンダー追加用メールを受け取る`が有効だったか確認します。
- `COMMON_CALENDAR_ID`が正しいか確認します。
- GAS実行アカウントが対象カレンダーを編集できるか確認します。
- `Reservations`シートの`GoogleEventId`と`CalendarId`を確認します。

### 案内メールが届かない

- 入力したメールアドレスと迷惑メールフォルダを確認します。
- 件名`[機器予約]`で検索します。
- `authorizeMailService`を実行して権限を承認したか確認します。
- Apps Scriptの実行履歴とMailAppの送信上限を確認します。

予約自体が保存され、メール送信だけに失敗した場合、GASは成功レスポンスを返しつつ実行ログにメール送信エラーを記録します。

### GitHub Pagesの変更が反映されない

- GitHub ActionsまたはPagesのデプロイ完了を確認します。
- ページを強制再読み込みするか、シークレットウィンドウで確認します。
- `index.html`内の`?v=`を変更します。
